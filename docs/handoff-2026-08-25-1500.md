"Verified" = a real server of that version started with the jar, paired

How it is built: `companion/gradlew` (9.5.1) + foojay toolchains; Fabric
targets in `fabric/targets/<mc>` with era shims in `fabric/compat/<era>`;
Forge the same under `forge/` (its own wrapper; EventBus 6→7 at 1.21.6).
Adding a version = new `targets/<mc>` dir, compile-probe an era, bench,
extend the ranges in `companion/build.gradle`. `make build` does everything.

The bench: `/srv/mc-matrix/bench.sh` + README. It pairs through a SQL-only
integration so the running app never loads it — a loaded bench network
would page the owner about every stopped server. Delete it before restarts.

## Deliberately not done

- NeoForge (no companion at all; the mainstream modded loader today).
- Forge 1.20.x (ForgeGradle 6, SRG-obfuscated runtime — needs reobf).
- Fabric/Forge 1.20.5–1.20.6 (short-lived; untested, so not claimed).
- Item icons for 26.x items (sulfur etc.) — they fall back to text labels;
  see the `homehub-mc-textures` memory for regenerating from a client jar.
- Prettier is not configured for `web/`; do not reformat.

## Gotchas learned

- Paper ≤1.16.5 refuses Java 17+; Paper 1.13.2 wants positional `nogui`.
- A Forge jar's `loaderVersion` floor must be the oldest Forge major it
  claims, not the one it was built on.
- The auto-mode classifier blocks reading the DB URL from the systemd unit;
  rolled-back `psql` transactions and the service journal are the substitutes.
