## 1. What this is, in one page

**HomeHub** (`/root/homehub`) is a self-hosted homelab control plane: Go 1.25
backend, React 19 + Vite 6 + Tailwind v4 + TanStack Router/Query + Radix
frontend, PostgreSQL 17. About 63k lines of Go and 63k lines of TS/TSX. It
runs as a systemd unit on this VM and the owner uses it daily against real
infrastructure — **this is production, not a sandbox.**

- **Owner**: Philipp, app user `philipp` (Owner role), Telegram chat linked.
  Reaches the app through Caddy at `https://smarthomegup.de`.
- **Spec-first API**: `api/openapi.yaml` is the source of truth. `make
  generate` regenerates `internal/api/gen.go` (oapi-codegen strict server)
  and `web/src/lib/schema.d.ts` (openapi-typescript). Streaming and
  unauthenticated routes are raw chi handlers on distinct paths.
- **Migrations**: goose, `internal/db/migrations`, applied at startup.
  Latest is `00034_calendar_feeds.sql`.
- **Secrets**: `internal/vault`, AES-GCM envelope, master key at
  `data/master.key` (never in the DB — back it up). Secrets go in over the
  API and never come back out.
- **Realtime**: one multiplexed WebSocket at `/api/ws`, every topic
  authorized per subscriber in `authorizeTopic` (`internal/app/app.go`).
- **RBAC**: `internal/rbac`, deny-by-default, resource-path subtree grants
  with view / control / configure / delete. Denied resources are hidden
  (404), not disabled (403 only when the caller can see the thing).
- **Feature inventory**: `docs/FEATURES.md` is complete and current.
  `README.md` is the pitch plus install and service instructions.

## 2. Hard rules

1. **Never touch host auth, credentials, or system config.** No passwords,
   keys, sshd/PAM/sudoers/firewall/network edits, ever. On Aug 17 a session
   changed root's password and sshd config for a test and locked the owner
   out of their own machine: "That cannot happen again... ever." Anything
   needing a login gets a dedicated new unprivileged user. Persistent
   system config (units, cron, `/usr/local/bin`) only when the owner asks —
   the unit and `homehubctl` symlink were explicitly requested.
2. **The connected systems are the owner's real infrastructure.** Proxmox
   "ServerPH Cluster", Home Assistant, TrueNAS, Aperture NVR, the AcardiaMC
   Minecraft network, AMP, Tailscale, Caddy, the Sovol Zero printer,
   PatchPilot hosts. Reads only. Never fire lifecycle actions, service
   calls, console commands, or restarts at them for testing. Shutting things
   down = "shutting yourself off". When a live check is needed, pick a
   target that touches nothing remote (the PatchPilot integration is a
   local-only driver; the "HomeHub VM" Docker instance is the local socket).
3. **UX stays unintrusive.** No MFA prompts, no re-auth walls, no
   confirmation dialogs on ordinary actions. Confirmations exist only for
   destructive ones.
4. **Verify before claiming.** The owner has caught agents asserting a fix
   worked when it had not. Check the built bundle, the database, the
   journal, or the live provider. Part 9 has the techniques.
5. **The owner reads the diffs.** Comments explain why, never what. Match
   the surrounding density. No stubs, placeholders, or fake data — omit an
   unbuilt feature rather than show a dead control.
6. **Never bulk-delete through text-matched UI selectors.** A Playwright
   cleanup script once deleted three real integrations. Name-gate every
   destructive click.
7. **The Minecraft bench integration must not be loaded by the running app.**
   If you create one via SQL for `/srv/mc-matrix/bench.sh`, delete it before
   any HomeHub restart or every stopped bench server pages the owner.

### 4.2 The integration manager

`internal/integration/manager.go`. One runner goroutine per enabled
instance: `Open` → first `Health` verdict decides the status (inbound
drivers open fine while the upstream still has to call in) → `watch` loop
with health and collect ticks → unreachable means close and reconnect from
scratch with exponential backoff (5 s → 2 min).

- `Apply(id)` stops the runner, re-reads the row, relaunches. Used after
  create/update and by the new **Reload** action. It stops *before* it
  re-reads and only relaunches on a successful read — never hand it a
  cancellable request context.
- `Kick(id)` nudges a runner out of backoff or into an instant health check
  (the Minecraft registry uses it on companion bind/drop).
- Secrets are read per attempt through `Deps.Secret` (vault scope
  `integration:<id>`), SSH registry bindings resolved per attempt
  (`sshbinding.go`), so edits apply on the next reconnect.
- WS topic is `integration:<type>/<id>`; `PublishScoped` delivers only to
  clients with view on the specific child resource. Status changes go on
  the `integrations` topic.
- Metric resources are `<type>/<integration uuid>/…`; orphan series of
  deleted integrations are GC'd every 5 min; quiet series of live
  integrations deliberately stay.

### 4.3 API conventions

- Handler shape: identity → load row → `visibleUnder` (404 if not) →
  `s.can(level)` (403) → do → `s.audit.Log(ctx, actorFor(id),
  "domain.verb", resource, "success", details)`.
- Errors: `errBody(code, message)` wrapped in the generated
  `NotFound/Forbidden/Conflict…JSONResponse` helpers.
- New WS topic → add an `authorizeTopic` case. New periodic work →
  `jobEngine.Register` + `EnsureSchedule`. New endpoint → spec first, then
  `make generate`, then the handler.
- `UpdateIntegration` replaces config wholesale — editors must spread the
  existing config to preserve keys they do not show (bit the Caddy link).

### 4.4 Signals and notifications

`internal/signals`: collectors (`Name/Interval/Collect → []Observation`)
for integration status, TrueNAS alerts, HA batteries, PatchPilot runs,
backups, Proxmox nodes/storage, Docker restart loops, Tailscale key expiry,
Aperture camera health, Minecraft per-server offline, trash pickups. The
reconciler upserts keyed conditions in place (`signals` table, partial
unique index on live key), flips `auto_resolve` rows to `recovered` when a
sweep stops reporting them, and treats a **dismissed row as a suppression
marker**: same/lower severity → quiet touch, escalation → reopen, condition
clears → re-arm. `last_seen` moves only on visible change. **The store
reuses one undismissed row per key**, so `first_seen` on a reopened row is
the *original* first sighting — do not narrate it as "down since".

Telegram pushes (`internal/api/api_notices.go`), since Sep 4 in three
layers. **Gate** (`gateNotice` → drop / queue / send): 30-minute floor per
condition unless worse; recoveries park 10 minutes in
`signal_notices.recovery_due_at`, withdrawn if the fault returns, dropped
if never reported; a return within `flapWindow` (6 h) of a sent all-clear
is judged against `last_fault_severity`, not "recovered" (that comparison
was the spam engine), and is queued unless worse; a key with `flaps > 0`
inside its window is queued always. **Policy** (`internal/notices`, stored
as setting `notice_policy`, UI card `web/src/pages/notice-policy.tsx` in
the Telegram dialog): `RouteFor(severity, now)` = immediate or digest,
quiet hours with `criticalDuring`, digest times per weekdays/weekends or
per day, IANA timezone. **Queue** (`notice_queue`, migration 00038, one
live row per key; repeats refresh, all-clears set `resolved_at`, returns
bump `bounces`). `FlushDigest` runs on the minute sweep beside
`FlushRecoveries`; `DigestDue(last, now)` finds scheduled instants in
(last, now], last check in memory, last digest sent persisted as
`notice_digest_last`. An immediate message carries the queue as
`NoticeInput.Queued` and flushes it as "immediate"; the digest is written
by `assistant.WriteDigest` (fallback `TemplateDigest`) and logged under key
`digest`. Narrator input has `Flaps`. `UpsertSignal` resets `first_seen`
and `count` when a recovered row re-fires; the reconciler reports such a
re-fire as "new", not "escalated". Collector-side dwell windows: 3 min
before reporting a fault, 15 min before believing a recovery. Assistant
context: `Access.ContextLines` carries the last 24 h of sent alerts on
Telegram; `historyTurns` keeps only the newest 6 alert rows.

### 4.5 The assistant

`internal/assistant/service.go` runs the turn loop (≤6 tool rounds, 30-row
history window, tool results fenced and labelled untrusted). Tools call the
app's own API through `api.SelfCall` under the calling user's identity, so
RBAC and audit apply verbatim; the SelfCall must clear the outer chi route
context (`chi.RouteCtxKey → nil`) or every inner route decodes an empty
body — a test pins this. Destructive tools return a `PendingAction` that
pauses the turn until the user approves; approval output re-enters as a
fenced user-role turn. SSH commands pass `sshguard` (allowlist runs
unattended, unknown needs approval, catastrophic refused outright).

Conversations are trees (`parent_id`, `on delete cascade` — **never prune
that table by row age**; web prune goes by the conversation's newest row,
Telegram keeps the newest 200 per user and unhooks survivors first).
Providers: Anthropic Messages, OpenAI Chat Completions, Gemini; 16 registry
entries incl. local runtimes; per-provider keys in vault slots
`assistant/api-key-<provider>`. Prompt caching splits the system prompt into
a byte-identical `Base` (cache breakpoint) and a per-user `Context`. Cost is
computed at write time (cache reads 0.1×, writes 1.25×). Auto routing is a
rule table in `autoroute.go`. `normalizeTurns` merges assistant runs so
Telegram threads that open with pushed alerts satisfy role alternation.

The Telegram bridge (`internal/telegram`) long-polls one bot; a chat links
to a user with a code minted by the bot on `/link` and entered in the web
panel, so the secret only flows Telegram → web. Only one chat is linked.

### 4.7 Other systems, the non-obvious parts

- **Proxmox**: guest consoles use the guest-scoped `vncwebsocket` path;
  node-level 401s. Both WS legs set a 64 MiB read limit (a waking VM's
  framebuffer blows the 32 KB default and the library *closes* the socket).
  Serial console sends termproxy's `"2"` app-level ping.
- **TrueNAS 26**: REST is gone; JSON-RPC over WS at `/api/current`.
  User-linked API keys need the owning username (`auth.login_ex`). The NAS
  serves its full method schema unauthenticated at `/api/docs/current`.
- **Home Assistant**: native WS, `state_changed` → cache + publish; non-%/
  bytes units map to the `decimal` chart kind.
- **Docker**: SDK pinned `v26.1.5+incompatible` with `go-connections v0.5.0`
  (v0.8 breaks it).
- **AMP**: `Core/Login` is camelCase, everything else PascalCase; a stopped
  instance answers `{"Title":"Instance Unavailable"}` before auth; no
  scrollback API exists, so the console ring is history-since-connect.
- **Caddy**: HomeHub is a *client* of the owner's `caddy-reader` helper
  (vendored under `helper/caddy-reader`, own Go module). The splitter never
  parses — byte-exact round trip. Cloudflare link: DNS ops go straight from
  store + vault, never through the helper; published sites inherit the
  inferred site template (a site without `tls dns cloudflare` on this LAN
  can never get a cert).
- **Moonraker**: object set discovered at runtime; `SET_HEATER_TEMPERATURE
  HEATER=` wants the Klipper *config name* (text after the first space).
  Snapshot crosses to the API via a JSON round-trip — keep both sides' tags
  identical or fields vanish silently.
- **PatchPilot**: agentless SSH; onboarding installs a `patchpilot` user with
  least-privilege sudoers and a `from="<HomeHub source IP>"`-pinned key
  (`bootstrap.go`, `hardenedAuthorizedKey`). Since Sep 4 a host can be
  **bound to an SSH registry entry** (`patchpilot_hosts.ssh_host_id`,
  migration 00035): the entry's address is dialed on every connection
  (`Registry.Endpoint`, snapshot synced back), its key or password does the
  bootstrap (`ppLoginFromRegistry` in `api_patchpilot.go`, control on the
  entry required), and a typed password is only the sudo password when the
  entry is key-based — `Detect` reports `needsPassword` and the wizard asks
  then. Runs still use the managed account and the fleet key. `Rebootstrap`
  (`POST …/hosts/{hostId}/rebootstrap`, "Set up again" in the UI) re-runs
  the bootstrap over that credential and is the repair for a stale `from=`
  pin; it verifies the pinned host key rather than replacing it. **Edit**
  (per row in the host table and on the host page, `edit-host.tsx`) is the
  add form again: binding via the binding endpoint, then name / auto-reboot
  / manual address via `PUT …/hosts/{hostId}` — which accepts `hostname` and
  `sshPort` for manual hosts only and answers `address_bound` for bound ones.
  **Last-run signal** (`patchpilotCollector` in `internal/signals/collectors.go`):
  one key per fleet, `pp:<fleet>:lastrun`, auto-resolving with the text
  "Last update run succeeded"; the run id sits in the detail, and
  `lastRunChanged` sets `Recur` only when the observed run differs from the
  row on record (live or dismissed), which is what lets a *new* failure
  reopen after a dismissal while the *same* failure stays quiet. The
  PatchPilot page shows it as a banner with Dismiss (`LastRunNotice` in
  `module.tsx`, matched by `detail.kind === "last-run"` because the API does
  not expose the key). Fleet health no longer reflects run outcomes.
  Migration 00036 acknowledged the old per-run rows once. **Abort semantics:**
  `AbortRun` cancels the run context only; the remote apt-get keeps running
  (`executeHostRun` records the host as `cancelled` with a message saying
  so, the run as `cancelled`, and neither produces a signal). The next run
  waits for that leftover lock instead of exiting 100 — the failure the
  owner hit on Sep 4 after aborting mid-upgrade. Two layers: apt's own
  `-o DPkg::Lock::Timeout=600` (`aptLock`) covers dpkg's lock only — apt 2.6
  still fails the cache lock on `/var/lib/apt/lists/lock` on the spot — so
  `aptLockWait` prefixes every apt step with `pp_wait_apt`, which reads
  `/proc/locks` for a write lock on apt's or dpkg's lock files (up to ten
  minutes, one log line). Gotchas that cost time: `stat %t/%T` are the
  device-node numbers, `%D` is the filesystem device the lock table keys on
  (glibc dev_t split in shell arithmetic); `/proc/locks` is filtered by pid
  namespace, so a holder outside a container is invisible inside it — bench
  holders must run in the container (perl `flock` works, apt-get check does
  not take the cache lock, `-s dist-upgrade` neither). `RecoverPatchpilotRuns`
  now actually runs at startup (it existed, unwired). **Skip a host mid-run**
  (`POST …/runs/{runId}/hosts/{hostId}/skip`, `Registry.SkipHost`): every host
  runs under its own child context (`hostContext`), the skip set is checked
  before a host starts and again when its stream ends, so a queued host is
  "Skipped by operator" and an in-flight one is skipped with the
  keeps-running note; the run continues. Same control permission as abort. The pin is
  the *source address of the bootstrap connection*: `localhost` dials `::1`
  here, so a name that flips between address families breaks the pin — use
  IPs in registry entries. `SSHConn.RunScript` pipes base64 through
  `/bin/sh` (login shells may be non-POSIX). Never share one `bytes.Buffer`
  between stdout and stderr with `x/crypto/ssh` — it races and drops output;
  `internal/integrations/minecraft/ssh.go` still has that latent bug.
- **Aperture**: video streams direct from the NVR to the browser (WebRTC →
  MSE fallback, `live-engine.ts`); RTSP credentials are stripped at the
  struct level.
- **Calendar**: masters carry RRULE + `EXDATE[]` (NOT NULL → empty slice,
  never nil); all-day events are UTC dates, derive local spans from
  `getUTC*` parts. Feeds: `/calendar/feed/<token>.ics`, unauthenticated, the
  token is the credential.
- **SSH registry**: `ResolveSSHForResource` is the single lookup every SSH
  consumer uses; a dangling binding fails closed. Host keys pin on first use.

## 8. Gotchas — read before touching the frontend

Each of these cost real time and is invisible until production.

**Tailwind / CSS**
- `app.css` has an **unlayered** global `:focus-visible` outline; unlayered
  CSS beats layered utilities regardless of specificity, so
  `focus-visible:outline-none` silently loses. Escape hatch:
  `data-focus-ring="none"`.
- **tailwind-merge resolves by category, last wins**: `relative` next to
  `fixed` un-fixes; `hidden` next to `flex` wins.
- `hover:` is gated behind `@media (hover: hover)`; a hover-revealed control
  is invisible on touch. Use `opacity-100 … [@media(hover:hover)]:opacity-0`.
- `data-theme` is always set on `<html>`, so canvas code may read
  `--hh-*` tokens via `getComputedStyle(document.documentElement)`.
- `img{max-width:100%}` from the reset clips pixel-art overlays; set
  `maxWidth:none` where a sprite must overflow its cell.

**Radix**
- A modal Dialog sets `pointer-events:none` on `<body>`; `ui/dialog.tsx` runs
  `modal={false}` and re-implements click-away.
- **`DialogContent` mounts even when closed** — only the Portal's children
  are gated. Effects there run on every page that renders a closed dialog
  (caused a reload-surviving scroll lock; the lock now lives in a
  `ScrollLock` inside the portal).
- Open a Dialog from a DropdownMenu `onSelect` as a state-controlled
  sibling, not nested in the menu.
- `Tooltip.Trigger asChild` stamps its own `data-state` over a Switch's;
  key Switch styling off `aria-checked`.

**uPlot**
- `points:{show:false}` draws nothing for one- or two-point series while the
  tooltip reports values; show markers when sparse.
- The x-axis auto-ranges to the data, not the window; pin `scales.x` to the
  requested range (also stops a collapsed x-range dragging y with it).
- Dedupe axis labels in `values`; size a fixed axis to the widest label.
- Only `kind="decimal"` follows the data (`chartYRange`); percent/bytes/count
  read from zero on purpose.

**Runtime / browser**
- The owner browses an **insecure LAN origin** at times: no `crypto.subtle`,
  `crypto.randomUUID`, `navigator.clipboard`, or WebAuthn. Use
  `lib/utils` `randomId()`/`copyText()`, `js-sha*` for hashing; passkey UI
  hides on `!window.isSecureContext`. Walk against the LAN origin, not
  127.0.0.1.
- TanStack Router swallows `#hash`; scroll targets manually
  (`useHashFocus`). Heading-slug counters must be per render or TOC ids drift.
- `hover`-less mobile calendar arrows stay where the finger is (b68fe64).

**WebSockets / SSH**
- `coder/websocket` 32 KB default read limit *closes the connection*; raise it
  on both legs of anything that proxies frames.
- Term sessions are one-time tickets (30 s claim TTL); reconnect mints a
  fresh session via the `renew` prop.
- `x/crypto/ssh` copies stdout and stderr in separate goroutines; never
  point both at one plain buffer.
- On the Minecraft host the first exec session's stdout is dropped; judge by
  exit code. `screen` subcommands return non-zero normally — no `set -e` in
  those scripts.

**LLM**
- Prompt caching is a byte-prefix match; never interpolate per-user text
  into `Base`. Minimums are not monotonic (Haiku 4.5: 4096 tokens, Sonnet 5:
  1024, Opus 5: 512) and a prompt silently fails to cache.
- Haiku fabricates plausible numbers when asked to be brief or add context;
  forbid earlier readings/causes/remedies explicitly, give it a true
  comparison instead, and never put a literal figure in a "wrong" example
  (it gets copied; a test guards this).
- A model's judgement is not a rate limiter — the deterministic gate runs
  first.
- Model ids were looked up, not recalled: `claude-haiku-4-5`
  (`-20251001`), `claude-sonnet-5`, `claude-opus-5`, `claude-fable-5`;
  OpenAI `gpt-5.6-luna/-terra/-sol`. OpenAI reasoning models need
  `reasoning_effort:"none"` with function tools.

**Backend**
- `RowToStructByNameLax` errors on extra SQL columns.
- `assistant_messages.parent_id` cascades on delete (rule above).
- `UpsertMinecraftServer`'s `paired_at` must be table-qualified vs `EXCLUDED`.
- Mongo driver v2 decodes nested docs as `bson.D`; use typed structs.
- `ClientIP` honours forwarded headers only from configured trusted proxies.
- `make build` must run from the repo root; from `web/` it "succeeds" doing
  nothing and the restart redeploys the old binary.

## 9. Verification playbook

What actually worked when something had to be *known*.

**Read the database.** Read-only selects are free; rehearse anything
destructive under `begin; …; rollback;`.

```bash
PGPASSWORD=homehub psql -h 127.0.0.1 -U homehub -d homehub -tAc "select …"
```

**Call the API as the test admin.** Mint a session row directly — never
touch passwords. Cookie name is `homehub_session`. Delete the row after.

```bash
ADMIN=$(PGPASSWORD=homehub psql -h 127.0.0.1 -U homehub -d homehub -tAc "select id from users where username='admin';")
TOKEN=$(python3 -c "import secrets;print(secrets.token_urlsafe(32))")
HASH=$(printf '%s' "$TOKEN" | sha256sum | cut -d' ' -f1)
PGPASSWORD=homehub psql -h 127.0.0.1 -U homehub -d homehub -tAc "insert into sessions (user_id, token_hash, expires_at, ip, user_agent) values ('$ADMIN', decode('$HASH','hex'), now() + interval '2 hours', '127.0.0.1', 'agent-verify') returning id;"
curl -s -w ' %{http_code}\n' -X POST -H "Cookie: homehub_session=$TOKEN" http://127.0.0.1:8080/api/…
PGPASSWORD=homehub psql -h 127.0.0.1 -U homehub -d homehub -tAc "delete from sessions where user_agent='agent-verify';"
```

**Read the journal**, filtered: `journalctl -u homehub --since "10 minutes
ago" -o short-precise | grep -v 'connect failed\|unhealthy after'`. Driver
connects, companion binds, notice gating ("held back", "parked") all log
here. `journalctl --list-boots` and `-b -1` for the previous boot.

**Check the built bundle**, not the source, when a fix "did not land":

```bash
grep -o 'index-[A-Za-z0-9_-]*\.js' web/dist/index.html
grep -c "someUniqueString" web/dist/assets/index-XXXX.js
```

**Pure TS logic**: copy the function into `$SCRATCHPAD/x.mjs` and run it
under node. There is no test runner.

**Go**: `go test ./internal/...`; live PatchPilot tests with `PP_LIVE=1
go test ./internal/integrations/patchpilot/`; `go test -race` on anything
with goroutines and buffers.

**Live model probes**: a throwaway Go test that opens the pool with the DSN

## 10. Incident on record: the address change

Found today while answering "why do 5 of 6 Minecraft hosts not work".

- All six companions were connected until HomeHub stopped at 19:10 on
  Sep 2 (no disconnects logged). The VM came back at 19:49 with
  `192.168.20.141`; not one companion connected during that entire boot.
- Five servers were paired from the LAN origin, so their
  `homehub-companion.properties` `url` is `http://192.168.20.142:8080`. They
  last arrived from `192.168.20.192` directly. Nobody owns `.142` now
  (ARP incomplete), so they time out and retry forever. Reload cannot help:
  they dial us.
- `smp` arrives via Caddy (`192.168.20.67`) — the domain path — and works.
  It blipped at 21:09:05 exactly when the owner's `caddy.publish` reloaded
  the proxy.
- PatchPilot's `from="192.168.20.142"` key pins on every managed host are
  broken the same way.
- Options given to the owner: a router DHCP reservation restoring `.142`
  (fixes both, nothing else touched; host network config is theirs), or
  re-pointing the five `url=` lines at the domain plus a server restart
  each (the plugin reads the file at start; do **not** re-pair, that makes a
  new server row) and Repair on each PatchPilot host. The Minecraft host's
  SSH is reachable from here via the registry if the owner wants an agent
  to do the edits — with their go-ahead only.

**Resolution (Sep 3, 22:03).** The owner chose a static address,
`192.168.20.26`, and ran `/root/network-static/apply.sh` from the console.
The first version of that script installed the static stanza *before*
`ifdown`, so ifdown used the static method and never told dhcpcd to stop;
with `persistent` in `dhcpcd.conf` it re-leased `.141` on the link bounce,
re-added its default route and rewrote resolv.conf seconds after the script
had finished — leaving both addresses on the interface. `finish.sh`
(release the lease, default route via `.26`, write resolv.conf) completes
the cutover, and apply.sh's order is corrected for the record. Lesson for
ifupdown: `ifdown` first, then change the file, then `ifup`. Verified on
Sep 4: `.26` only, static route and resolver, no dhcpcd, no restart needed.
