## 1. The machine, in one page

**HomeHub** (`/root/homehub`) is a self-hosted homelab control plane: Go 1.25
backend, React 19 + Vite + Tailwind v4 + TanStack Router/Query frontend,
PostgreSQL. It runs as a systemd unit on this host and is reachable at
`https://smarthomegup.de`. The owner (Philipp, `philipp`) uses it daily —
this is production, not a sandbox.

- **API**: chi + oapi-codegen strict handlers. `api/openapi.yaml` is the
  source of truth; `make generate` regenerates the Go interfaces and the
  typed TS client. Some routes are raw chi (streaming ones).
- **Migrations**: goose, `internal/db/migrations`, applied at startup. Latest
  is `00032_signal_notices.sql`.
- **Secrets**: `internal/vault`, AES-GCM, master key at `data/master.key`.
  Secrets go in and never come back over the API.
- **Realtime**: one multiplexed WebSocket (`/api/ws`), RBAC-authorized per
  topic.
- **RBAC**: `internal/rbac`, deny-by-default, resource-path subtree grants
  with view/control/configure/delete.
- **Full feature inventory**: `docs/FEATURES.md` (written this session, current).

### The deploy loop — get this exactly right

```bash
make build      # NEVER from web/ — it will silently do the wrong thing
systemctl restart homehub
systemctl is-active homehub
```

- `make build` compiles the frontend into `web/dist` and embeds it in `bin/homehub`.
- **Before staging: `git checkout -- helper/dist/`.** The build regenerates
  helper binaries; committing them bloats every diff.
- Typecheck alone: `npm --prefix web run typecheck` (from repo root — running
  it from a subdirectory resolves `web/` relative to the cwd and fails).
- There is **no frontend test runner**. Pure TS logic gets verified by copying
  the function into a scratch `.mjs` and running it under `node` (see §8).
- Go tests: `go test ./internal/...`.

## 3. What happened this session (33 commits)

Roughly four arcs. Newest first within each.

### A. SSH host registry (`92a9612`, `c7a34b5`, `5e6f3d3`)

One central place to manage every machine HomeHub can reach over SSH, replacing
credentials typed into each feature.

- `internal/api/api_sshhosts.go` — CRUD, test, terminal, and
  **`ResolveSSHForResource`**, the single lookup every SSH consumer uses
  (bound registry host wins, else the resource's inline credential).
- `internal/store/sshhosts.go`, `internal/sshguard/` (command risk
  classifier for assistant-issued commands — fails closed, 40+ tests).
- **One-click provisioning**: enter host + user → generates an ed25519 pair,
  installs it into `authorized_keys` idempotently, verifies by reconnecting
  with the key, then stores. Live-verified against `pp-target1`.
- `internal/integration/sshbinding.go` — generic resolution: a config with
  `sshHostId` gets the host's hostname/port/user/authType written into the
  plain keys drivers already read, and the secret served from the vault. Docker
  and Minecraft both use it; drivers know nothing about the registry.
- Frontend: `web/src/pages/ssh-hosts.tsx` exports **`SSHHostPicker`**, reused
  in the PVE guest page and the systems editor.

**Deferred, deliberately**: auto-importing existing PVE guest credentials into
the registry. Existing systems keep working on inline credentials; switching is
opt-in.

### B. Proxmox resource tree (`d1e4dbf`)

`web/src/pages/pve/tree.tsx` — a Server View-style sidebar (datacenter → nodes

### C. The assistant — the bulk of the session

This is where most of the work went. Current state:

| Feature | Where |
|---|---|
| Pause/resume on confirmed actions | `internal/assistant/service.go` (`RunActionOutcomes`), `internal/api/api_assistant_stream.go` |

| Telegram persona | `internal/assistant/service.go` (`telegramPersona`) |
| Notification narrator | `internal/assistant/narrator.go` |

Key design decisions worth preserving:

- **A queued action pauses the turn; it does not end it.** Approving runs the
  actions, feeds their output back to the model, and it finishes the answer.
  The output arrives in a *user-role* turn (no `tool_use` id survives), so it
  is fenced and labelled untrusted — `outcomePrompt` in `service.go`. Tests
  pin that framing.
- **Conversations are trees.** `parent_id` on `assistant_messages`; the client
  walks one path (`buildPath`), branch choices live in sessionStorage beside
  the conversation id so they share a lifetime.
- **Auto mode routes by a rule table, never by model self-assessment** — the
  owner was explicit about this. `ClassifyLane` matches named patterns (asks
  why / challenges the answer / asks for judgement / asks for diagnosis / asks
  to plan / long question). Auto never routes to a gated model; a test enforces
  it as the catalog grows.
- **Model IDs are real and were looked up, not recalled.** Anthropic:
  `claude-haiku-4-5` (the only one with a dated snapshot,
  `claude-haiku-4-5-20251001`, kept as an alias), `claude-sonnet-5`,
  `claude-opus-5`, `claude-fable-5`. OpenAI: the **GPT-5.6** family —
  `gpt-5.6-luna` / `-terra` / `-sol`. The app's old `gpt-5` default was stale.
- **Cost is computed at write time**, not derived on read: with caching the
  same token counts bill at three rates and the split is unrecoverable from a
  total. Cache reads are 0.1×, writes 1.25×.

### D. Signals → Telegram, written by a model (`f82ca86` … `9793cc4`)

The push notifications are now written by a small model (Haiku 4.5), chosen
independently of the chat model on the assistant page.

- `internal/assistant/narrator.go` — `WriteNotice` returns
  `{send, text, why}`. It can **hold a message back** (a repeat that has not
  worsened) and says why in the log.
- **The templated text is the fallback**, not the default: no model, no key,
  an unparseable answer → `telegramSignalText` in `internal/app/app.go`. Only
  a *deliberate* hold sends nothing. The two paths are distinct in code so a
  failure can never masquerade as judgement.
- Sent alerts are appended to the recipient's Telegram assistant thread
  (`RememberSentNotice`), so you can reply to one and the bot knows what "that"
  is. This required `normalizeTurns` — see §7.
- **Flap protection, three layers** (`9793cc4`, after a 16-hour storm):
  dwell windows in the collector (3 min before reporting, 15 min before
  believing a recovery), a deterministic 30-minute floor per condition checked
  *before* the model is asked, and notice records that survive recovery.

## 7. Gotchas — read before touching the frontend

These each cost real time. They are not obvious and several are invisible
until production.

**Tailwind / CSS**

- `app.css` has an **unlayered** global `:focus-visible { outline: 2px … }`.
  Unlayered CSS beats Tailwind's layered utilities *regardless of specificity*,
  so `focus-visible:outline-none` on an element silently loses. The escape
  hatch is `data-focus-ring="none"`, defined in `app.css` alongside the rule.
- **tailwind-merge resolves conflicts by category, last-wins.** Adding
  `relative` next to `fixed` un-fixes the element. Adding `hidden` next to
  `flex` wins. This bit me on the dialog.
- **`hover:` is gated behind `@media (hover: hover)`.** A control revealed only
  on hover is permanently invisible on touch. Use
  `opacity-100 … [@media(hover:hover)]:opacity-0` instead.
- Theme tokens live under `:root[data-theme="light"|"dark"]`. `data-theme` is
  always set on `<html>` (`web/src/lib/theme.ts`), so
  `getComputedStyle(document.documentElement).getPropertyValue("--hh-…")`
  works — canvas code depends on this.

**Radix**

- A modal `Dialog` sets `pointer-events: none` on `<body>`. That is why the
  assistant widget was unclickable over an open dialog. `web/src/ui/dialog.tsx`
  runs `modal={false}` and re-implements click-away dismissal.
- **`DialogContent` mounts even when the dialog is closed** — only the Portal's
  *children* are gated on open state. An effect in `DialogContent` therefore
  runs on every page that merely renders a closed dialog. This caused a
  permanent, reload-surviving scroll lock. The lock now lives in a `ScrollLock`
  component *inside* the portal.
- Opening a Radix Dialog from a DropdownMenu `onSelect` works, but render the
  dialog as a sibling controlled by state, not nested in the menu.

**uPlot**

- `points: {show: false}` means a series is only visible as the *line between*
  its samples. A one- or two-point series draws **nothing**, while the tooltip
  happily reports its values. Show markers when the data is sparse.
- The x-axis auto-ranges to the **data**, not the window — nine hours of
  samples stretch across a chart labelled "7d". Pin `scales.x` to the requested
  range. This also removes a failure mode where a collapsed x-range drags the
  y-axis with it (uPlot ranges y over the visible x window).
- Axis label formatting can collapse distinct ticks onto identical text (a
  per-minute axis spanning 0–0.07 renders seven `0/min` labels). Dedupe in the
  `values` callback.
- A fixed axis `size` clips longer labels. Size it to the widest label.

**WebSockets**

- `coder/websocket` has a **32 KB default per-message read limit** and
  *closes the connection* when exceeded. A waking VM's full framebuffer redraw
  blows straight past it. Both legs of the PVE console now call
  `SetReadLimit(64 << 20)`. Symptom: black screen, then a disconnect loop, with
  no error anywhere.

**Anthropic / LLM**

- **Prompt caching is a prefix match on exact bytes.** The system prompt is
  split into `System{Base, Context}` — `Base` is byte-identical for everyone on
  a surface and carries the cache breakpoint; `Context` is the per-user line
  and sits after it. Interpolating a name into `Base` gives every user their
  own cache entry and shares nothing.
- Cache minimums are **not monotonic**: Haiku 4.5 needs a 4096-token prefix,
  Sonnet 5 needs 1024, Opus 5 only 512. A prompt can silently not cache with no
  error.
- **Haiku fabricates plausible numbers when asked to be brief or to add
  context.** It did this three times: "up from 88% forty hours ago", "roughly
  24 hours before it's full", "last seen 7 hours 42 minutes ago" — all
  invented. Fixes that worked: forbid earlier readings/causes/remedies
  explicitly, *give it a true comparison to use instead* (the stored previous
  severity), and make sure tools are actually available (with tools it calls
  them instead of guessing).
- **A concrete number inside a "wrong" example gets copied.** Labelling `88%`
  as wrong did not stop it being reused — it was the nearest matching text.
  Examples now carry no literal figures, and a test fails if one reappears.
- **Providers disagree about role alternation.** A Telegram thread can open
  with an assistant message and carry several in a row, because HomeHub pushes
  alerts into it. `normalizeTurns` (in `service.go`) merges runs and folds a
  leading run of alerts into the first user turn as quoted context — dropping
  them would satisfy the API and defeat the feature.
- **A model's judgement is not a rate limiter.** The narrator holds repeats
  back and usually does it well, but anything that flaps will outrun it. The
  deterministic 30-minute floor exists for that reason and runs *before* the
  model is asked.

## 8. Verification playbook

What actually worked when I needed to know something rather than guess.

**Read the database directly.** Faster and more certain than reasoning about
the API:

```bash
sudo -u postgres psql homehub -c "select …"
```

This is how I found that the History series had 9 points spanning 77.8–385.0
MB, which proved the chart was holding one point — from the axis labels alone.

**Probe the backend with a throwaway Go test.** Pattern (delete it afterwards):

```go
// internal/api/tmp_probe_test.go
pool, _ := pgxpool.New(ctx, os.Getenv("HOMEHUB_DATABASE_URL"))
v, _ := vault.Open(pool, os.Getenv("HOMEHUB_DATA_DIR"), "", logger)
key, _ := v.Open(ctx, "assistant", "api-key-anthropic")
provider, _ := assistant.NewProviderFor(assistant.Config{Provider: "anthropic", APIKey: string(key)})
```

```bash
HOMEHUB_DATA_DIR=/root/homehub/data \
HOMEHUB_DATABASE_URL="$(grep -oP 'HOMEHUB_DATABASE_URL=\K\S+' /etc/systemd/system/homehub.service | tr -d '"')" \
go test ./internal/api/ -run TestProbe -v -count=1
```

This is how the narrator's voice, the hold-back behaviour, and the
prompt-injection resistance were all verified against the **live model** before
shipping. Do this — the prompts are the product here, and reading them is not
the same as running them.

**Check the built bundle**, not the source, when the owner says a fix did not
land:

```bash
grep -o 'index-[A-Za-z0-9_-]*\.js' web/dist/index.html
grep -c "someUniqueString" web/dist/assets/index-XXXX.js
```

**Verify pure TS logic under node** by copying the function into
`$SCRATCHPAD/x.mjs`. There is no test runner; this is the substitute. Used for
`chartYRange`, `usageLine`, `buildPath`.

**Telegram**: only one chat is linked (`6771665693`, Philipp). Demo sends go
through the bot API directly with the token from the vault
(`telegram`/`bot-token`); bracket them with a framing message so a demo outage
does not send the owner to check a real printer.
